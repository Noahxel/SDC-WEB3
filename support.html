1 — Du Zombie au Badge

Chaque concept appris dans CryptoZombies a son équivalent direct dans SkillBadge.sol.

CryptoZombies Concept Dans SkillBadge.sol
Ch. 1 pragma solidity
Déclarer la version du compilateur 		pragma solidity ^0.8.0;
Ch. 1 contract NomDuContrat { }
Structure de base d'un contrat 		contract SkillBadge { }
Ch. 2 uint, variables d'état
Stockées sur la blockchain (coûtent du gas) 		uint256 issuedAt dans la struct
Ch. 4 struct
Regrouper plusieurs variables sous un même type 		struct Badge { address, string, uint256, address }
Ch. 5 Type[] public tableau
Tableau dynamique stocké sur la blockchain 		Badge[] public badges
Ch. 5 tableau.push(valeur)
Ajouter un élément à un tableau 		badges.push(Badge(...))
Ch. 6 function nom(...) external
Fonction appelable depuis l'extérieur 		function issueBadge(...) external
Ch. 8 view
Lecture seule — gratuit à appeler, pas de gas 		getBadge(...) external view
Nouveau mapping(K => V)
Table clé-valeur — accès direct par clé 		mapping(address => uint256[])
Nouveau event + emit
Log permanent sur la blockchain, visible sur Etherscan 		event BadgeIssued(...) / emit BadgeIssued(...)
Nouveau msg.sender
L'adresse qui appelle la fonction 		msg.sender → stocké comme issuer
Nouveau block.timestamp
Horodatage du bloc en cours (secondes Unix) 		block.timestamp → stocké comme issuedAt

2 — SkillBadge.sol annoté

Lisez chaque ligne. Les commentaires expliquent le pourquoi, pas seulement le quoi. 

// Licence open-source — requis par le compilateur depuis Solidity 0.6.8
// SPDX-License-Identifier: MIT

// Version du compilateur — le ^ signifie "0.8.x mais pas 0.9"
pragma solidity ^0.8.0;

contract SkillBadge {

    // ── TYPES ──────────────────────────────────────────────────────────────

    // Un Badge = les 4 informations qui définissent une certification
    struct Badge {
        address student;   // adresse Ethereum de l'étudiant certifié
        string  skill;     // nom de la compétence  ex: "Solidity Basics"
        uint256 issuedAt;  // timestamp Unix  ex: 1717200000  (secondes depuis 1970)
        address issuer;    // adresse qui a signé la certification
    }

    // ── ÉTAT (stocké sur la blockchain) ────────────────────────────────────

    // Tous les badges, dans l'ordre de création
    // 'public' → Solidity génère automatiquement badges(0), badges(1), etc.
    Badge[] public badges;

    // Pour chaque adresse : la liste des index de ses badges dans le tableau ci-dessus
    // ex: badgesByStudent[0xABC] = [0, 3, 7]  → l'étudiant a les badges #0, #3, #7
    mapping(address => uint256[]) public badgesByStudent;

    // ── EVENTS (logs permanents) ────────────────────────────────────────────

    // Émis à chaque nouveau badge → visible dans Etherscan → écoutable par les DApps
    // 'indexed' = filtrable : "tous les badges de cet étudiant" sans lire tout le contrat
    event BadgeIssued(
        address indexed student,
        string  skill,
        uint256 issuedAt,
        address indexed issuer
    );

    // ── FONCTIONS D'ÉCRITURE (coûtent du gas) ──────────────────────────────

    // Certifier une compétence pour un étudiant
    // 'external'  = appelable de l'extérieur seulement (pas dans le contrat)
    // 'calldata'  = paramètre en lecture seule, moins cher en gas que 'memory'
    function issueBadge(address student, string calldata skill) external {
        uint256 index = badges.length;  // index qu'aura ce badge dans le tableau

        badges.push(Badge(
            student,
            skill,
            block.timestamp,  // horodatage fourni par le validateur du bloc
            msg.sender        // adresse qui appelle cette fonction (l'émetteur)
        ));

        badgesByStudent[student].push(index);  // référencer ce badge pour cet étudiant
        emit BadgeIssued(student, skill, block.timestamp, msg.sender);
    }

    // ── FONCTIONS DE LECTURE (gratuites) ───────────────────────────────────

    // 'view' = ne modifie pas l'état → pas de transaction, pas de gas

    function getBadgeCount() external view returns (uint256) {
        return badges.length;
    }

    function getBadgesOf(address student)
        external view returns (uint256[] memory)  // 'memory' obligatoire pour retourner un tableau
    {
        return badgesByStudent[student];
    }

    function getBadge(uint256 index)
        external view
        returns (address, string memory, uint256, address)
    {
        Badge memory b = badges[index];
        return (b.student, b.skill, b.issuedAt, b.issuer);
    }
}

4 — Erreurs fréquentes

✗ "Injected Provider - MetaMask" n'apparaît pas dans la liste
→ MetaMask n'est pas installé ou pas activé sur ce navigateur. Installer l'extension depuis metamask.io puis recharger Remix.
✗ Solde affiché = 0 ETH dans Remix
→ Aller sur sepoliafaucet.com → coller l'adresse MetaMask → recevoir 0.5 ETH de test. Attendre ~30 secondes.
✗ MetaMask affiche "Réseau incorrect" ou le réseau n'est pas Sepolia
→ Dans MetaMask, cliquer sur le nom du réseau en haut → "Afficher les réseaux de test" → sélectionner Sepolia.
✗ La compilation échoue avec "Source file requires different compiler version"
→ Dans le panneau Compiler, changer la version pour 0.8.19 ou toute version 0.8.x.
✗ Le bouton Deploy est grisé ou inactif
→ Le contrat n'est pas compilé. Aller dans le panneau Solidity Compiler → cliquer Compile SkillBadge.sol → revenir dans Deploy.
✗ La transaction MetaMask reste en "pending" longtemps
→ Normal sur Sepolia — attendre jusqu'à 60 secondes. Si ça dépasse 2 minutes, vérifier la connexion internet. Pas besoin de renvoyer.
✗ "Gas estimation failed" dans MetaMask
→ L'adresse dans le champ "student" est invalide. Vérifier qu'elle commence par 0x et fait 42 caractères.
✗ Le contrat déployé disparaît de Remix après un rechargement
→ Normal — Remix ne sauvegarde pas les contrats déployés. L'adresse est toujours valide sur Sepolia. Dans Deploy & Run → "At Address" → coller l'adresse pour le retrouver.

5 — Glossaire

TermeDéfinition
address Identifiant unique sur Ethereum. 20 octets, commence par 0x. Ex: 0x287...4eF
ABI Application Binary Interface. Le schéma des fonctions d'un contrat — dit à ethers.js/web3.py comment encoder les appels.
block.timestamp Horodatage Unix du bloc en cours (secondes depuis le 1er janvier 1970). Fourni par le validateur.
calldata Zone mémoire des paramètres d'entrée d'une fonction. Lecture seule. Moins cher que memory pour les strings.
event Log émis sur la blockchain lors d'une transaction. Permanent, indexé, visible sur Etherscan. Ne coûte pas cher en gas.
external Visibilité d'une fonction : appelable uniquement depuis l'extérieur du contrat. Préférable à public pour les fonctions d'entrée.
gas Unité de coût computationnel de l'EVM. Chaque opcode a un coût fixe. Les frais de transaction = gas utilisé × gas price.
Gwei 10⁻⁹ ETH. Unité utilisée pour exprimer le gas price.
keccak256 Fonction de hash utilisée par Ethereum (variante de SHA-3). Produit une empreinte de 32 octets.
mapping Table de correspondance clé → valeur. Accès en O(1). Pas itérable nativement.
memory Zone mémoire temporaire — existe le temps d'une exécution de fonction. Obligatoire pour retourner des tableaux ou strings.
msg.sender L'adresse Ethereum qui a envoyé la transaction appelant la fonction courante.
Sepolia Réseau de test Ethereum (testnet). Comportement identique au mainnet mais ETH sans valeur réelle.
storage Zone mémoire persistante — les variables d'état du contrat. Chère à écrire (SSTORE = 20 000 gas).
view Modificateur de fonction : ne modifie pas l'état. Appel gratuit — pas de transaction, pas de gas.
wallet Interface gérant une paire clé privée/publique. Ne "contient" pas de tokens — ceux-ci sont sur la blockchain.
